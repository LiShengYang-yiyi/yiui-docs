# 排查

> 资源问题的第一分界线是「包有没有初始化成功」。包没起来，后面所有加载都会失败或拿到空。

**关键词**：Package initialize · 加载资源包失败 · 清单缺失 · 图集加载失败 · 引用计数 · 句柄未释放

## 1 启动阶段

| 日志 | 含义 | 处置 |
|---|---|---|
| 加载资源包失败 | 按包名取不到包对象 | 确认建包那一步已执行、包名一致 |
| 初始化UI失败 | 上游拿到初始化失败的返回 | 先解决上面那条 |
| 包已存在 | 同一包名被建了两次 | 建包只做一次 |
| 初始化未完成 / 初始化失败 | 包对象被提前使用 | 检查是否早于就绪事件就加载资源 |
| 找不到有效的清单 | 清单没更新或缺失 | 检查清单文件与版本请求 |

初始化本身重复调用只会打一条警告，不会报错 —— 所以「初始化了但没生效」通常不是初始化的问题。

## 2 加载阶段

| 症状 | 根因 |
|---|---|
| 拿到空对象，无异常 | 资源名不对，或承载资源为空 |
| 编辑器报错、真机静默 | 有效性校验只在编辑器里跑 |
| 加载成功但显示空白 | 加载到的对象类型不对 |
| 图集内的图取不到 | 图集数据没重新生成 |

**加载失败时句柄会被主动释放**，所以不会留下悬空句柄，但也意味着失败是静默的 —— 业务要自己判空。

## 3 图集四类失败日志

| 日志 | 处置 |
|---|---|
| 验证资产有效性 没有这个资源 | 精灵名写错，或图集数据未生成 |
| 加载失败 没有这个资源 | 同上，加载阶段才发现 |
| 找到图集但没有找不到Sprite | 图集数据里的映射与图集内容不一致，重跑一次图集生成 |
| 重复添加Sprite | 同名精灵被登记两次，检查图集拆分 |

## 4 引用计数与释放

三条容易混淆的点：

1. **两层计数**：底层按句柄数，上层按「包名 + 资源名」分组。上层归零才归还底层。
2. **两条链路不共享句柄表**：ET 侧与 YIUI 侧各自记账，跨链路混用会导致一方以为还在用、另一方已经释放。
3. **上层分组键里，空包名被归一成固定字符串** —— 它与资源包的默认包名不是一回事，排查计数时别混。

释放侧的行为：

- 重复释放单个句柄是静默的
- 但底层在计数已归零时再被要求释放会直接抛异常
- 组件销毁时只做整批释放，**不清上层句柄记录** —— 若销毁后仍有上层记录残留，需要额外确认

## 5 编辑器与真机行为差异

| 差异 | 编辑器 | 真机 |
|---|---|---|
| 资源来源 | 直接读工程目录 | 读打包产物 |
| 资源名校验 | 会校验 | 不校验 |
| 界面根节点查找 | 场景里先 `Find` 一次 | 只能靠加载 |

编辑器里 `Find` 命中会**跳过加载** —— 场景残留的根节点会掩盖加载问题，排查时先清理场景。

## 6 并发与锁

工程里存在两套加载锁，**互不通**：

| 链路 | 锁 |
|---|---|
| YIUI 侧 | 界面加载锁，键是资源名哈希 |
| ET 侧 | 资源加载锁，键是地址哈希 |

同资源被两条链路同时加载时不会互相等待，各自向底层取一次。正常情况下底层会复用，但排查「加载了两次」时要考虑这个因素。

## 7 改动清单速查

| 想改什么 | 改哪 |
|---|---|
| 运行模式 / 宿主地址 | 资源配置文件 |
| 打包内容 | 收集器设置 |
| 地址命名规则 | 收集器设置里的地址规则 |
| 清单文件名 / 内容根目录 | 资源包设置文件 |
| 版本段的地址 | 代码里的常量 |
| 包名 | 建包调用处 + 本包初始化默认值 |

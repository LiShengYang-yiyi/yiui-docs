# 阶段 7 · 工具链与 AI 协作

> **一句话**：这个工程把「编译门禁、Unity 操作、UI 拼接、行为树、测试」都做成了可被 AI 调用的接口——这一阶段讲怎么用它们，而不是怎么手动做。

前六个阶段讲的是「这个框架怎么工作」。最后这一阶段讲的是「**这个工程为你准备了什么**」。

这套工具链的设计目标和一般工程不同：它不是为人设计的效率工具，而是**为 AI 设计的执行入口**。判断标准是「AI 能不能在没有人在场的情况下完成发现、执行、验证、修正的闭环」。

## 一条贯穿全部的设计原则

> **AI 走的是接口，不是界面。**

| 允许 | 禁止 |
|---|---|
| 经 YIUIMCP / UTO 调用 Unity 编辑器、资源、编译、Console | AI / CLI 直接调用 Unity API |
| 用职责单一、参数最少的 MCP 工具 | 手写 HTTP 绕过编排层 |
| CLI 用于 CI / Shell / 排障 | 把 CLI 当作主入口 |

原因很实际：直接调 Unity API 需要处理线程、域重载、编辑器状态，这些在无人在场时全是坑。接口层把这些都收口了。

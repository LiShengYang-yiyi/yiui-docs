# 阶段 6 · YIUI 客户端 UI

> **一句话**：YIUI 用 CDE 三张表（Component / Data / Event）把「数据」和「具体控件」解耦——写 UI 逻辑时只操作数据与回调，不关心控件是什么。

前面五个阶段讲的是 ET：实体、分层、消息、服务端链路。**YIUI 是跑在 ET 上的 UI 层**，它回答的是「客户端界面怎么写」。

它解决的核心问题是：**UI 代码不要长成「找到控件 → 调用控件的 API」的样子。**

传统写法：

```
找到名叫 txtName 的 Text 控件 → 调用它的 text 属性 → 赋值
```

YIUI 的写法：

```
设置数据 Name = "xxx" → 绑定了 Name 的文本自动更新
```

差别在于**谁需要知道控件**。第一种写法里，业务逻辑知道控件类型；第二种写法国，业务逻辑只知道数据。于是同一个数据可以驱动多个控件，业务代码不用改。

## 一条贯穿本阶段的边界（最重要）

YIUI 的 Panel / View **只负责表现与交互**。

| 禁止 | 正确做法 |
|---|---|
| UI 里 `new` 请求消息、`Call` / `Send`、等回包 | 由客户端业务组件统一发起请求 |
| UI 自己缓存业务数据副本 | 只读业务组件提供的数据 |
| UI 写协议 `try/catch`、判断错误码 | 统一由协议错误提示工具收口 |

> 这是 ET 客户端侧最容易被越界的地方。规则原文见 `AGENTS.md`（工程根）的「ET 分层与客户端边界」。

# 阶段 0 · 环境

> **一句话**：在动手之前，先把「要装什么」和「东西都放在哪」弄清楚。

这个阶段不写业务代码。它解决的是另一类问题：**环境不对，后面每一步都会卡。**

版本选错、缺 IL2CPP、没挂代理、权限不够——这几类问题会让工程连编译都过不去，而报出来的错往往看不懂。与其后面逐个撞上，不如先一次性排掉。

后面所有阶段都默认这一阶段的前提已经成立：工程能编译、知道代码该放哪、知道哪些文件不能手改。

| [0.2 工程目录与构建入口](./2-project-layout) | 目录职责、包内分层、哪些文件不能手改 | 知道代码该放哪 |

## 前置

无。这是整条路线的起点。

## 做完之后你应该能回答

- 这个工程锁定哪个 Unity 版本？为什么不能随便换？
- 为什么服务端必须用管理员权限启动？
- 服务端编译的唯一入口是什么？
- 新增一个功能，代码该放进 `Packages/<某个包>/Scripts/` 的哪个目录？
- 哪些文件禁止手动修改？

五个都能答出来，就可以进阶段 1 了。

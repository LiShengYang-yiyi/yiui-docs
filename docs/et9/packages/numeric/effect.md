# 数值影响

~~使用数值监听功能 监听到需要的数值变化后 手动修改对应的想修改的值~~

~~这样的自由度最高 可以1对多的影响 也不用限制影响公式~~

但是 这仅限于 独立开发 如果是团队开发的情况下

::: danger 💀 没有深入了解不懂的情况下 不建议使用此功能
:::

个人还是更愿意把这些开放给策划 至少某些情况下策划可以自行调整

而不会因为某个小小的改动就要找程序

优点

1. 这个是底层上去做的数值影响  跟使用NumericChange这个事件有本质区别
2. 程序省心 扩展度 自由度更高
3. 使用配置 策划可以没有程序介入的情况下扩展功能

(不要说什么策划水不会写代码...  那都不是问题 数值策划会的你相信我)

缺点

要在配置表裸写代码要求是高一点 (但是也就高一点)

简单的加减乘除那种很简单的  如果对于复杂的需求 第一版可以考虑在编辑器里写拷贝过去就好了

以后要修改某个值的大小时 就可以交给策划了

## 归纳

影响主要分为3个大类 举例:

### 覆盖

如案例中的等级变化会强制修改目标结果一样

不需要考虑之前什么情况

可以直接写返回什么值

![](/images/et9/img/Kohjb885gomqTVxelovcnNJlnpg.png)

### 改变

战斗力 之类的 都需要考虑

因为他的改变是来自多个地方的

当前数值的影响只是一部分

如  战斗力可能被  力量,智力,敏捷 影响 这些值又各不同

那么 当其中一个改变时 不能单纯的覆盖值  所以是使用+= 改变操作

这种就要考虑如何还原的问题

![](/images/et9/img/ZGolbVC0foz3eDxlnT9crKMKnoe.png)

如:这里的公式    当前值 + (新值 - 老值) \* 2 = 最终的速度

假设 速度 初始 1000   最大血量=0的情况  那么 这个结果就是 1000的速度

当增加 500点最大血量时   结果就是   1000 + (500-0) \* 2 = 2000的速度

又修改血量变为300   结果就是  2000 + (300 - 500) \* 2 = 1600的速度

最后把血量改为0  结果就是 1600 + (0-300)\*2 = 1000的速度

所以不管怎么改变都可以得到想要的值  达到需求

### 条件

根据不同的条件 复杂的公式 决定在那种情况下应该怎么修改值

![](/images/et9/img/TlBMbGlNCouBFjxO6C3cEzHOncg.png)

## 注意

到底使用何种模式完全归功于你的公式怎么写

特别是改变类的 你要实现如何还原

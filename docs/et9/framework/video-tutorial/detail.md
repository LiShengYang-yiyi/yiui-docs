## 二 YIUI框架概述 **(15分钟)**

**(纯理论 也可以跳过直接看后面)**

- **名称由来**：YIUI名称取自“亦”字，谐音“易”，旨在成为一个易于使用且简单的框架。
- **设计理念**：结合多年工作经验和多个项目的实战总结，特别适用于大型项目，强调UI表现层与数据层的分离，提高开发效率和代码清晰度。

#### 核心特性

1. **分离设计**：将UI表现层与数据层进一步分离，逻辑层不依赖于具体的UI组件，数据变化驱动UI更新。
2. **简化使用**：减少逻辑层的复杂性，界面的打开、关闭、回退、加载等操作由框架管理。
3. **分布式设计**：支持多层UI管理，适应复杂的项目结构。
4. **分块式加载**：按需加载UI组件，提高性能和效率。
5. **多样化打开方式**：支持多种参数和方法打开UI，包括无限参数和配置文件触发。
6. **自适应设计**：支持自适应刘海屏等现代设备特性。
7. **生命周期管理**：参考MonoBehaviour的生命周期，为UI组件提供完整的生命周期管理。
8. **回退功能**：支持复杂的界面回退操作。
9. **动画管理**：支持自定义和统一管理UI的打开和关闭动画。

#### UI绑定

- **组件绑定**：可绑定所有unity mono组件。
- **数据绑定**：支持基础数据类型和自定义数据类型的绑定。
- **事件绑定**：实现一对多的事件响应，简化事件处理逻辑，支持同步与异步事件。

#### 扩展性和自动化

- **扩展性**：支持在MonoBehaviour上实现的功能扩展，提高UI与数据和事件的绑定效率。
- **自动化**：提供全套自动化支持，减少注册代码的编写，提高开发效率。

#### 演示和实际应用

- **演示**：通过一个简单的demo展示UI框架的使用和运行方式。
- **扩展插件**：介绍YIUI已有的扩展插件，如无限循环列表、GM命令、Tips界面、多语言、红点提示等，并提供实际案例。

#### 总结

YIUI框架是一个为大型项目设计的UI框架，它通过分离UI表现层和数据层，简化了UI的开发和管理。框架提供了丰富的特性，如分布式设计、分块式加载、多样化打开方式等，以适应不同的项目需求。同时，YIUI还提供了UI绑定方案，简化了组件、数据和事件的绑定过程，并通过自动化减少了开发中的重复劳动。整个框架的设计旨在提高开发效率，使开发者能够更专注于逻辑实现，而不是UI的具体操作。

## 四 流程更新 (30分钟)

#### 更新流程概述

- **分支管理**：首先需要了解项目中不同分支的作用，如状态同步分支、YIUI状态同步分支和开发分支。
- **识别更新**：确定哪个分支需要更新，并在Unity中打开对应的项目。

#### 更新ET的状态同步包

1. **检查更新**：在包管理工具中查找需要更新的包。
2. **更新包**：根据实际情况选择更新到最新版本或特定版本。
3. **编译和测试**：更新后编译项目并运行测试，确保无错误。
4. **处理自动生成文件**：忽略自动生成的文件，如DLL和自动生成的类文件。
5. **提交更改**：编写更新日志并提交更改到仓库。

#### 更新YIUI状态同步包

1. **查看更新日志**：了解YIUI 每个版本的更新内容。
2. **合并分支**：将更新合并到当前分支，解决可能出现的冲突。
3. **更新包管理工具**：确保包管理工具请求到最新的包更新。
4. **编译和测试**：更新后编译项目并运行测试，确保无错误。
5. **处理重复插件**：解决更新后可能出现的插件重复问题。

#### 同步到开发分支

1. **合并状态同步分支**：将状态同步分支的更改合并到开发分支。
2. **编译和测试**：在开发分支上编译项目并运行测试，确保无错误。
3. **解决冲突**：解决合并过程中出现的文件冲突和错误。
4. **上传同步**：将开发分支的更改上传到仓库。

#### 特殊情况处理

- **自动生成代码**：确保自动生成的代码如meta文件没有被错误地修改或删除。
- **热重载问题**：使用YIUI自带的事件功能已支持热重载。
- **版本升级问题**：解决因版本升级带来的不兼容问题，如invoke函数的参数变更。

#### 总结

ET框架的更新流程涉及多个分支的管理、包的更新、冲突解决和测试验证。这一流程要求开发者对Unity项目结构和Git版本控制有清晰的理解。同时，更新流程中需要特别注意自动生成文件的处理、插件重复问题的解决以及版本升级可能带来的不兼容问题。通过这一流程，开发者可以确保项目的持续迭代和维护，同时保证项目的稳定性和可靠性。
